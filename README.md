# برنامه ریز

وب‌اپ فارسی و راست‌به‌چپ برای دیدن برنامهٔ امروز، مدیریت تقویم و پیدا کردن زمان آزاد. نمایش اولیه شمسی، شروع هفته شنبه، ساعت ۲۴ساعته و منطقهٔ زمانی `Asia/Tehran` است. برنامه با Next.js App Router، TypeScript strict و Tailwind CSS ساخته شده است. Vazirmatn همراه خود برنامه سرو می‌شود.

## اجرای محلی

Node.js نسخهٔ ۲۲ یا ۲۴ و npm لازم است. فرمان‌ها را از ریشهٔ همین ریپازیتوری اجرا کنید.

```bash
npm ci
npm run dev
```

در مرورگر `http://localhost:3000` را باز کنید. بار اول برنامه بدون رویداد باز می‌شود. «بارگذاری دادهٔ نمونه» در داشبورد اختیاری است و فقط رویدادها و کارهای ساختگی را وارد می‌کند.

```bash
npm run lint
npm run typecheck
npm test
npm run build
npm start
```

برای تست مرورگری، Chromium را نصب کنید و تست را اجرا کنید. Playwright سرور توسعه را روی پورت ۳۱۰۰ راه می‌اندازد.

```bash
npx playwright install chromium
npm run test:e2e
```

در محیطی که Chromium از قبل نصب است می‌توانید مسیر آن را با `PLAYWRIGHT_CHROMIUM_EXECUTABLE` مشخص کنید. برای تست یک سرور در حال اجرا، آدرس آن را با `PLANNER_TEST_URL` بدهید.

## گردش کار

- داشبورد برنامهٔ جاری یا بعدی، فهرست زمانی، جمع ساعات آزاد و اشغال‌شده و اولین بازهٔ آزاد باقی‌ماندهٔ امروز را نشان می‌دهد. در **عقب‌افتاده‌ها** می‌توان تا سه زمان جایگزین برای کار زمان‌بندی‌شده یا مطالعهٔ انجام‌نشده دید و پس از مقایسهٔ زمان قبلی و جدید، همان رویداد را جابه‌جا کرد. برای سری‌های مطالعه، ۳۰ روز اخیر به‌طور پیش‌فرض بررسی می‌شود و می‌توان نوبت‌های قدیمی‌تر را دید. اگر مهلت تعیین شده باشد، پیشنهادها تا پایان همان روز محدودند.
- تقویم چهار نمای ماه، هفته، روز و فهرست دارد. در خط زمانی می‌توان روی یک ساعت کلیک کرد. تغییر تاریخ، ساعت و مدت رویداد از فرم ویرایش انجام می‌شود. فیلتر و جست‌وجو فقط روی نمایش رویدادها اثر دارند.
- تکرار روزانه، هفتگی چندروزه و ماهانه را می‌توان بدون پایان، تا یک تاریخ یا با تعداد محدود ثبت کرد. تکرار ماهانه بر اساس روز ماه در تقویم انتخابی سری است و ماه کوتاه‌تر رد می‌شود. تاریخ پایان تکرار شامل همان روز است. تداخل رویداد تکراری تا یک سال از شروع سری بررسی می‌شود.
- در **درس‌ها** می‌توان کلاس، امتحان، تکلیف و جلسهٔ مطالعه ایجاد کرد یا از فرم ویرایش به درس مرتبط کرد. در جزئیات درس، روزهای باقی‌مانده و مدت مطالعهٔ برنامه‌ریزی‌شده تا امتحان نمایش داده می‌شوند. برای امتحان بدون ساعت، مرز محاسبه ابتدای روز امتحان است.
- در **تنظیمات ← زمان‌های ترجیحی** می‌توان برای هر دسته چند روز و ساعت تعریف کرد. در پیشنهاد کار و در تقویم روزانه یا هفتگی، زمان آزادِ مطابق ترجیح بالاتر می‌آید و گزینهٔ خارج از ترجیح برچسب دارد. رفت‌وآمد قبل و بعد از رویداد در پیشنهادها مسدود است و حاشیهٔ استراحت به بازه‌های اشغال‌شده افزوده می‌شود. جمع زمان آزاد و اشغال‌شدهٔ داشبورد از ساعات فعال و طول خود رویدادها محاسبه می‌شود.
- برای هر درس یا دسته، هدف هفتگی قابل تنظیم است. هدف درس از جلسات مطالعه و هدف دسته از رویدادهای زمان‌دار همان دسته محاسبه می‌شود. داشبورد زمان انجام‌شده، زمان برنامه‌ریزی‌شده و میزان باقی‌مانده را جدا نشان می‌دهد.
- در نمای هفته، **کپی برنامه به هفتهٔ بعد** رویدادهای مستقل را با پیش‌نمایش تداخل‌ها نشان می‌دهد. می‌توان زمان مقصد را تغییر داد یا مواردی را از انتخاب خارج کرد. رویدادهای کپی‌شده در وضعیت برنامه‌ریزی‌شده ذخیره می‌شوند و درس و دسته را حفظ می‌کنند.
- برای کارهای بدون زمان، پیشنهادها با مدت و مهلت کار سازگارند. بدون مهلت، ۳۰ روز آینده بررسی می‌شود. می‌توانید بین بازه‌های هفت‌روزه جابه‌جا شوید و گزینه‌های بیشتری در هر بازه ببینید. لغو یا حذف رویداد مرتبط، کار را به فهرست انتظار برمی‌گرداند.
- در صفحهٔ **تبدیل ساعت** می‌توانید منطقهٔ مبدأ و ساعت را با قالب AM/PM انتخاب کنید و معادل آن را در تهران و شهرهایی مانند سائوپائولو، نیویورک، لندن و دبی و ساعت‌های ثابت EST، GMT و WAT ببینید. دکمهٔ «ثبت جلسه در تقویم» همان زمان را در فرم رویداد قرار می‌دهد.
- در صفحهٔ **یادداشت‌ها** می‌توانید یادداشت متنی با عنوان اختیاری بسازید، در عنوان و متن جست‌وجو کنید و یادداشت‌ها را ویرایش یا حذف کنید.
- هر رویداد می‌تواند یک لینک جلسه، تا ۱۰ لینک با عنوان دلخواه و تا سه PDF یک‌مگابایتی داشته باشد. PDF از جزئیات رویداد دانلود می‌شود. پیوست‌ها بخشی از سهمیهٔ localStorage هستند و انتخاب فایل در فرم تا زمان ذخیره به داده‌های برنامه اضافه نمی‌شود.

## محل ذخیره و انتقال داده

رویداد، پیوست، درس، دسته، کار، یادداشت، نام نمایشی، ترجیحات و هدف‌ها در localStorage با کلید `planner:data` و قالب نسخه‌دار ذخیره می‌شوند. رویداد زمان‌دار با زمان قطعی و منطقهٔ زمانی سری نگه داشته می‌شود. تاریخ تمام‌روز یک روز تقویمی است و با تغییر منطقهٔ زمانی جابه‌جا نمی‌شود. برنامه برای داده‌های شخصی سرور، دیتابیس یا API ندارد.

مرورگر، پروفایل، دستگاه، دامنه و پورت می‌توانند هرکدام فضای ذخیرهٔ جدا داشته باشند. همگام‌سازی بین دستگاه‌ها اختیاری است. تب‌هایی با origin یکسان تغییرات ذخیره را دریافت می‌کنند. اگر هنگام ویرایش داده‌ها عوض شوند، فرم قدیمی باید دوباره باز شود.

### اتصال گوشی و رایانه

در حالت عادی برنامه محلی کار می‌کند. برای دریافت آخرین نسخه حتی وقتی دستگاه دیگر خاموش است، می‌توانید یک مخزن خصوصی GitHub متعلق به خودتان را برای نگهداری فایل رمزگذاری‌شده انتخاب کنید. این قابلیت از API موجود GitHub استفاده می‌کند و به راه‌اندازی بک‌اند برنامه نیاز ندارد.

1. در GitHub یک مخزن جدا با حالت **Private** و گزینهٔ **Add a README file** بسازید. مقدار فیلد مخزن به‌شکل `owner/repository` است. [ساخت مخزن](https://github.com/new)
2. برای هر دستگاه یک **Fine-grained personal access token** بسازید. مالک مخزن را در **Resource owner** انتخاب کنید. در **Repository access** گزینهٔ **Only select repositories** را بزنید و فقط مخزن خصوصی همگام‌سازی را انتخاب کنید. در **Repository permissions**، مجوز **Contents** را روی **Read and write** بگذارید و توکن را هنگام نمایش در فیلد «توکن دستگاه» وارد کنید. [ساخت توکن](https://github.com/settings/personal-access-tokens/new)
3. در دستگاه دارای اطلاعات اصلی، از **تنظیمات ← اتصال دستگاه‌ها ← راه‌اندازی همگام‌سازی** نام مخزن و توکن را وارد کنید. با تأیید، اطلاعات شامل پیوست‌ها در مرورگر با کلید تصادفی ۲۵۶ بیتی و AES-GCM رمز می‌شود. فقط فایل رمزگذاری‌شده به GitHub ارسال می‌شود.
4. کد اتصال را خصوصی به دستگاه دوم منتقل کنید. در همان سایت، **ورود با کد اتصال** را بزنید و یک توکن با دسترسی به همان مخزن وارد کنید. پس از مشاهدهٔ تعداد کارها و رویدادها، می‌توانید بکاپ محلی بگیرید و دریافت اطلاعات را تأیید کنید.
5. پس از اتصال، برنامه هنگام باز شدن، بازگشت به تب، وصل شدن اینترنت، پس از ویرایش و هر دقیقه در تب فعال نسخه‌ها را بررسی می‌کند. دستگاه مبدأ باید پس از تغییرات فرصت ارسال داشته باشد. اگر هر دو دستگاه پیش از همگام‌سازی تغییر کرده باشند، **ادغام و همگام‌سازی** را بزنید تا تغییرات مستقل هر دو نسخه ذخیره شوند. برنامه آخرین نسخهٔ مشترک رمزگذاری‌شده را از مخزن می‌خواند و حذف‌های قابل تشخیص را رعایت می‌کند. در مواردی که یک رکورد در هر دو نسخه متفاوت تغییر کرده، نسخهٔ همان مورد را انتخاب کنید. برای متن متفاوت یک یادداشت، نگهداری هر دو به‌صورت دو یادداشت هم ممکن است. اگر نسخهٔ مشترک خوانده نشود، موارد موجود در فقط یکی از نسخه‌ها حفظ می‌شوند و حذف‌های قبلی قابل تشخیص نیستند. پیش از ادغام می‌توانید بکاپ هر دو نسخه را دانلود کنید.

هر اتصال فایل و کلید مستقل دارد. کد اتصال شامل کلید رمز است. توکن و کلید برای اتصال بعدی در پروفایل محلی دستگاه باقی می‌مانند و در بکاپ JSON قرار نمی‌گیرند. روی دستگاه مشترک از پروفایل مرورگر جدا استفاده کنید. قطع اتصال اطلاعات اتصال را از همان مرورگر حذف می‌کند. برای لغو دسترسی یک دستگاه، توکن مخصوص آن را در GitHub باطل کنید. نسخه‌های قبلی فایل رمزگذاری‌شده در تاریخچهٔ Git مخزن شما باقی می‌مانند.

### ثبت و مرور

دکمهٔ **ثبت سریع** در هدر و میانبر **N** از هر صفحه در دسترس‌اند. با نوشتن عنوان و فشردن Enter یک کار ثبت می‌شود. مدت و مهلت قابل انتخاب‌اند. برای تعیین ساعت، «ثبت به‌صورت رویداد» همان عنوان و مدت را به فرم تقویم می‌برد. آیکن ساعت کنار هر ورودی، انتخاب‌گر ۲۴ساعته با دقیقه‌های پیشنهادی و ورود دقیقهٔ دقیق را باز می‌کند. تایپ مستقیم ساعت هم در دسترس است. دکمهٔ خورشید یا ماه در هدر تم را عوض می‌کند. در صفحهٔ **مرور هفتگی** می‌توانید زمان هر دسته را بررسی کنید و وضعیت رویدادهای پایان‌یافته را از جزئیاتشان تغییر دهید.

### بکاپ و بازیابی

1. در **تنظیمات ← پشتیبان‌گیری و بازیابی**، **دانلود بکاپ JSON** را بزنید.
2. در مرورگر یا دامنهٔ مقصد، **بازیابی از فایل** را بزنید و فایل JSON را انتخاب کنید.
3. تاریخ بکاپ و تعداد رویدادها، دسته‌ها و کارها را بررسی کنید. در همین مرحله می‌توانید از وضعیت فعلی بکاپ بگیرید.
4. **تأیید جایگزینی** را بزنید. فایل پیش از ذخیره کامل اعتبارسنجی می‌شود. اگر ذخیره شکست بخورد، دادهٔ قبلی باقی می‌ماند.

بکاپ و دادهٔ محلی نسخه‌های ۱ تا ۴ هنگام خواندن به ساختار نسخهٔ ۵ تبدیل می‌شوند. بکاپ و همگام‌سازی شامل یادداشت‌ها و جلسه‌های واردشده از گوگل هم هستند. نسخهٔ جدیدتر، ساختار ناسالم و ارجاع‌های نامعتبر خطا می‌دهند. فایل بکاپ می‌تواند اطلاعات شخصی، لینک‌ها و پیوست‌ها را شامل شود. آن را در Git عمومی قرار ندهید. «حذف همهٔ داده‌های برنامه» تأیید جداگانه دارد و کلیدهای برنامه‌های دیگر را پاک نمی‌کند.

## اتصال به Google Calendar

1. در [Google Cloud Console](https://console.cloud.google.com/) پروژه‌ای بسازید و **Google Calendar API** را فعال کنید. در **Google Auth Platform**، نام برنامه و مخاطبان آن را تعیین کنید. اگر برنامه در وضعیت Testing است، حساب‌هایی را که قرار است متصل شوند به **Test users** اضافه کنید.
2. در **Clients** یک OAuth Client از نوع **Web application** بسازید. در **Authorized JavaScript origins** آدرس دقیق سایت، برای مثال `https://my-schedule-five-tan.vercel.app` را اضافه کنید. برای توسعهٔ محلی، آدرس و پورت دقیق مثل `http://localhost:3000` را جدا اضافه کنید. مسیر URL و Redirect URI برای این اتصال لازم نیست.
3. شناسهٔ عمومی OAuth را در **تنظیمات ← Google Calendar ← راه‌اندازی اتصال گوگل** وارد کنید. برای تنظیم شناسه به‌عنوان پیش‌فرض تمام کاربران نیز می‌توانید `NEXT_PUBLIC_GOOGLE_CLIENT_ID` را هنگام build در Vercel تنظیم کنید. Client Secret وارد نکنید.
4. **اتصال به Google Calendar** را بزنید و با حساب مدنظر اجازهٔ خواندن تقویم را بدهید. برنامه از `calendar.events.readonly` برای رویدادها و `calendar.calendars.readonly` برای شناسه و منطقهٔ زمانی تقویم اصلی استفاده می‌کند.

اتصال، جلسه‌های دارای لینک Meet را از ۳۰ روز قبل تا ۹۰ روز بعد وارد می‌کند. در تب فعال، تقریباً هر پنج دقیقه و هنگام برگشت به تب تغییرات بررسی می‌شوند. دکمهٔ «همگام‌سازی اکنون» برای دریافت فوری در دسترس است. توکن در حافظهٔ تب می‌ماند. بعد از رفرش، بستن صفحه یا پایان اعتبار، دوباره متصل شوید.

جلسه‌های واردشده در تقویم برنامه نمایش داده می‌شوند و مطابق وضعیت اشغال در گوگل می‌توانند در پیشنهاد زمان اثر بگذارند. تغییر ساعت، حذف یا لغو جلسه را در Google Calendar انجام دهید. قطع اتصال، رویدادهای قبلی را نگه می‌دارد. برای برداشتن آن‌ها از این برنامه، «حذف جلسه‌های واردشده» را بزنید. عنوان، زمان و لینک جلسات واردشده جزو داده‌های محلی، بکاپ و همگام‌سازی رمزگذاری‌شدهٔ دستگاه‌ها هستند.

## دیپلوی دستی روی Vercel

1. تغییرات بررسی‌شده را به ریپازیتوری GitHub خودتان منتقل کنید. در Vercel از **New Project** همین ریپازیتوری را Import کنید.
2. **Framework Preset** را روی **Next.js** و **Root Directory** را روی ریشهٔ ریپازیتوری بگذارید. Node.js **22.x** یا **24.x** را انتخاب کنید. تنظیمات پیش‌فرض نصب و build کافی‌اند و برنامه به متغیر محیطی نیاز ندارد.
3. **Deploy** را بزنید و پس از پایان build، آدرس اختصاص‌یافته را باز کنید.
4. برای انتقال برنامه‌های ثبت‌شده روی localhost، با همان مرورگر و پورت محلی بکاپ بگیرید. سپس در تنظیمات سایت منتشرشده روی Vercel همان فایل را بازیابی کنید.

## ساختار پروژه

- `src/app` صفحهٔ App Router، metadata، فونت و سبک‌ها
- `src/components` پوستهٔ تعاملی و کنترل‌های مشترک
- `src/features` داشبورد، تقویم و تبدیل تاریخ، رویداد و تکرار، زمان آزاد، کارها، تنظیمات و اعتبارسنجی بکاپ
- `src/lib` پیش‌فرض‌ها و خواندن و نوشتن localStorage
- `src/types` مدل داده
- `tests` تست‌های منطق و گردش کار مرورگر

تقویم از Temporal برای حساب تقویمی شمسی و میلادی و ساعت محلّی مناطق زمانی استفاده می‌کند. نمایش تاریخ با Intl بومی‌سازی شده است. رویدادهای تکراری فقط در بازهٔ لازم تولید می‌شوند.

## نقشهٔ راه

- حالت تمرکز و ثبت اختیاری مدت مطالعه
