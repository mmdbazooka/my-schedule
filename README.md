# برنامه‌ریز محمد

وب‌اپ فارسی و راست‌به‌چپ برای دیدن برنامهٔ امروز، مدیریت تقویم و پیدا کردن زمان آزاد. نمایش اولیه شمسی، شروع هفته شنبه، ساعت ۲۴ساعته و منطقهٔ زمانی `Asia/Tehran` است. برنامه با Next.js App Router، TypeScript strict و Tailwind CSS ساخته شده است. Vazirmatn همراه خود برنامه سرو می‌شود.

## اجرای محلی

Node.js نسخهٔ ۲۲ یا ۲۴ و npm لازم است. فرمان‌ها را از ریشهٔ همین ریپازیتوری اجرا کنید.

```bash
npm ci
npm run dev
```

در مرورگر `http://localhost:3000` را باز کنید. بار اول برنامه بدون رویداد باز می‌شود. «بارگذاری دادهٔ نمونه» در داشبورد اختیاری است و فقط رویدادها و کارهای ساختگی را وارد می‌کند.

```bash
npm run lint
npm run typecheck
npm test
npm run build
npm start
```

برای تست مرورگری، Chromium را نصب کنید و تست را اجرا کنید. Playwright سرور توسعه را روی پورت ۳۱۰۰ راه می‌اندازد.

```bash
npx playwright install chromium
npm run test:e2e
```

در محیطی که Chromium از قبل نصب است می‌توانید مسیر آن را با `PLAYWRIGHT_CHROMIUM_EXECUTABLE` مشخص کنید. برای تست یک سرور در حال اجرا، آدرس آن را با `PLANNER_TEST_URL` بدهید.

## گردش کار

- داشبورد برنامهٔ جاری یا بعدی، فهرست زمانی، جمع ساعات آزاد و اشغال‌شده و اولین بازهٔ آزاد باقی‌ماندهٔ امروز را نشان می‌دهد.
- تقویم چهار نمای ماه، هفته، روز و فهرست دارد. در خط زمانی می‌توان روی یک ساعت کلیک کرد. تغییر تاریخ، ساعت و مدت رویداد از فرم ویرایش انجام می‌شود. فیلتر و جست‌وجو فقط روی نمایش رویدادها اثر دارند.
- تکرار روزانه، هفتگی چندروزه و ماهانه را می‌توان بدون پایان، تا یک تاریخ یا با تعداد محدود ثبت کرد. تکرار ماهانه بر اساس روز ماه در تقویم انتخابی سری است و ماه کوتاه‌تر رد می‌شود. تاریخ پایان تکرار شامل همان روز است. تداخل رویداد تکراری تا یک سال از شروع سری بررسی می‌شود.
- تنظیمات ساعات فعال برای هر روز و حاشیهٔ استراحت را مشخص می‌کند. حاشیه قبل و بعد از برنامه‌های اشغال‌کننده به پیشنهادها اعمال می‌شود. جمع زمان آزاد و اشغال‌شدهٔ داشبورد از ساعات فعال و طول واقعی رویدادها محاسبه می‌شود.
- برای کارهای بدون زمان، پیشنهادها با مدت و مهلت کار سازگارند. بدون مهلت، ۳۰ روز آینده بررسی می‌شود. لغو یا حذف رویداد مرتبط، کار را به فهرست انتظار برمی‌گرداند.
- هر رویداد می‌تواند یک لینک جلسه، تا ۱۰ لینک با عنوان دلخواه و تا سه PDF یک‌مگابایتی داشته باشد. PDF از جزئیات رویداد دانلود می‌شود. پیوست‌ها بخشی از سهمیهٔ localStorage هستند و انتخاب فایل در فرم تا زمان ذخیره به داده‌های برنامه اضافه نمی‌شود.

## محل ذخیره و انتقال داده

رویداد، پیوست، دسته، کار و تنظیمات در localStorage با کلید `mohammad-planner:data` و قالب نسخه‌دار ذخیره می‌شوند. رویداد زمان‌دار با زمان قطعی و منطقهٔ زمانی سری نگه داشته می‌شود. تاریخ تمام‌روز یک روز تقویمی است و با تغییر منطقهٔ زمانی جابه‌جا نمی‌شود. برنامه برای داده‌های شخصی سرور، دیتابیس یا API ندارد.

مرورگر، پروفایل، دستگاه، دامنه و پورت می‌توانند هرکدام فضای ذخیرهٔ جدا داشته باشند. داده‌ها خودکار همگام نمی‌شوند. تب‌هایی با origin یکسان تغییرات ذخیره را دریافت می‌کنند. اگر هنگام ویرایش داده‌ها عوض شوند، فرم قدیمی باید دوباره باز شود.

### بکاپ و بازیابی

1. در **تنظیمات ← پشتیبان‌گیری و بازیابی**، **دانلود بکاپ JSON** را بزنید.
2. در مرورگر یا دامنهٔ مقصد، **بازیابی از فایل** را بزنید و فایل JSON را انتخاب کنید.
3. تاریخ بکاپ و تعداد رویدادها، دسته‌ها و کارها را بررسی کنید. در همین مرحله می‌توانید از وضعیت فعلی بکاپ بگیرید.
4. **تأیید جایگزینی** را بزنید. فایل پیش از ذخیره کامل اعتبارسنجی می‌شود. اگر ذخیره شکست بخورد، دادهٔ قبلی باقی می‌ماند.

بکاپ نسخهٔ ۱ به قالب فعلی تبدیل می‌شود. نسخهٔ جدیدتر، ساختار ناسالم و ارجاع‌های نامعتبر خطا می‌دهند. فایل بکاپ می‌تواند اطلاعات شخصی، لینک‌ها و پیوست‌ها را شامل شود. آن را در Git عمومی قرار ندهید. «حذف همهٔ داده‌های برنامه» تأیید جداگانه دارد و کلیدهای برنامه‌های دیگر را پاک نمی‌کند.

## دیپلوی دستی روی Vercel

1. تغییرات بررسی‌شده را به ریپازیتوری GitHub خودتان منتقل کنید. در Vercel از **New Project** همین ریپازیتوری را Import کنید.
2. **Framework Preset** را روی **Next.js** و **Root Directory** را روی ریشهٔ ریپازیتوری بگذارید. Node.js **22.x** یا **24.x** را انتخاب کنید. تنظیمات پیش‌فرض نصب و build کافی‌اند و برنامه به متغیر محیطی نیاز ندارد.
3. **Deploy** را بزنید و پس از پایان build، آدرس اختصاص‌یافته را باز کنید.
4. برای انتقال برنامه‌های ثبت‌شده روی localhost، با همان مرورگر و پورت محلی بکاپ بگیرید. سپس در تنظیمات سایت منتشرشده روی Vercel همان فایل را بازیابی کنید.

## ساختار پروژه

- `src/app` صفحهٔ App Router، metadata، فونت و سبک‌ها
- `src/components` پوستهٔ تعاملی و کنترل‌های مشترک
- `src/features` داشبورد، تقویم و تبدیل تاریخ، رویداد و تکرار، زمان آزاد، کارها، تنظیمات و اعتبارسنجی بکاپ
- `src/lib` پیش‌فرض‌ها و خواندن و نوشتن localStorage
- `src/types` مدل داده
- `tests` تست‌های منطق و گردش کار مرورگر

تقویم از Temporal برای حساب تقویمی شمسی و میلادی و ساعت محلّی مناطق زمانی استفاده می‌کند. نمایش تاریخ با Intl بومی‌سازی شده است. رویدادهای تکراری فقط در بازهٔ لازم تولید می‌شوند.

## نقشهٔ راه

- مرور هفتگی زمان برنامه‌ریزی‌شده و انجام‌شده به تفکیک دسته
- قالب رویداد، مدیریت ترم و استثناهای کلاس، و پیشنهاد چند جلسهٔ مطالعه تا مهلت امتحان
- حالت تمرکز و ثبت اختیاری مدت مطالعه
- ورود و خروج ICS با پیش‌نمایش و جلوگیری از تکرار
- PWA و رفتار آفلاین، یادآوری داخل برنامه و میانبرهای کیبورد
- ادغام اختیاری بکاپ، و جابه‌جایی و تغییر مدت رویداد با کشیدن
